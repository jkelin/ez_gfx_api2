# ez-gfx-compiler

Shader compiler library and offline `clap` CLI using `shader-slang` in-process sessions. They emit format-v3 `.ezgfxshader` artifacts containing the selected SPIR-V, DXIL, and/or Metal products, canonical reflection, provenance, and target-specific compatibility. Apple metallib builds record macOS platform, architecture, deployment minimum, SDK, Metal language, metallib contract, and Apple toolchain identity gathered at build time; development builds emit MSL with an explicit language contract. Each stage owns one artifact-internal entry point.

The public `compile_shader(source, targets, development)` interface accepts a `.slang` root source path, any nonempty subset of the `spirv`, `dxil`, and `metal` target families, and a development-mode flag. Every discovered stage is compiled for every selected target family. Target order is normalized, so permutations produce identical artifacts. Slang declarations provide entry names and stages; profiles are fixed internally. The function returns owned, validated artifact bytes without writing a file. The CLI uses the same inputs, writes beside the source by default, and accepts an optional output path. Runtime crates and packaged runtime distributions never depend on this crate or native compiler libraries.

Compiler and build environments require the native Slang shared library. `shader-slang` discovers a Vulkan SDK installation or `SLANG_DIR`/`SLANG_LIB_DIR`; DXIL additionally requires `dxil.dll` and `dxcompiler.dll`. Runtime packages depend on `ez-gfx-artifact`, not this crate or native compiler libraries.
